## 🔴 P0 - 阻塞问题

### NICE 编码错误

| 项目 | 内容 |
|------|------|
| **日期** | 2026-03-20 |
| **问题** | WLOAD/DLOAD 指令不生效 |
| **原因** | 使用 funct3 编码，但 E203 NICE 实际使用 bits[14:12] 作为 xd/xs1/xs2 |
| **教训** | E203 NICE 编码约定和标准 RISC-V 不同，必须看官方文档 |
| **解决** | 将操作码从 funct3 移到 funct7 |

## 🟡 P1 - 重要问题

### `nice_req_ready` 未设置 busy 状态

| 项目 | 内容 |
|------|------|
| **日期** | 2026-03-19 |
| **问题** | 协处理器在计算中仍接受新请求 |
| **原因** | 未在计算时拉低 `nice_req_ready` |
| **教训** | 握手信号必须正确实现 busy 逻辑 |
| **解决** | FSM 中计算状态时 `nice_req_ready <= 1'b0` |

### 复位清零不彻底

| 项目 | 内容 |
|------|------|
| **日期** | 2026-03-19 |
| **问题** | 复位后累加器值不确定 |
| **原因** | 复位信号未覆盖所有寄存器 |
| **教训** | 复位要覆盖所有状态元素 |
| **解决** | 显式 reset_n 赋值 |

### SDK 工具链不匹配

| 项目 | 内容 |
|------|------|
| **日期** | 2026-03-20 |
| **问题** | `-mtune=nuclei-300-series` 编译失败 |
| **原因** | 系统 riscv64-unknown-elf-gcc 版本不支持 |
| **教训** | 嵌入式开发要用 Nuclei 官方工具链 |
| **解决** | 下载官方 Nuclei GNU toolchain 2024.06 |

## 📝 教训总结

### 技术教训

1. **NICE 编码**: 一定要以官方文档为准，别套用标准 RISC-V 经验
2. **握手协议**: busy 信号不能忘，否则并发访问会出问题
3. **定点溢出**: INT8×INT8=INT16，累加多次要用 INT32
4. **仿真工具**: iverilog 版本很重要，文档要求的版本必须安装

### 流程教训

1. **先文档后代码**: 设计文档先行，避免返工
2. **小步提交**: 每个功能点单独 commit，方便回溯
3. **回归测试**: 每次修改后跑验证脚本
